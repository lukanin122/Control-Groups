# Аудит и архитектура Control Groups (Mindustry v160.7)

## Трактовка требований

Исходное задание: [план](../План-набросок%20Хотбара%20юнитов.txt), [правки V2](SPEC_V2.txt), [решения V2](V2_DECISIONS.md). Правила: [AGENTS.md](../AGENTS.md).

- Одно нажатие выбирает группу, тип или представителя проекции. Двойное дополнительно центрирует камеру. Для групп 1–9, 0 используются индексы ванильного массива 0–9.
- Составы только читаются из `InputHandler.controlGroups`. Мод не сохраняет вторую копию групп в настройках, не чистит ванильные ID и не меняет `distinctcontrolgroups`.
- Группа может временно содержать юнита под логикой/игроком. Его состояние показывается, но выбор пропускает юнитов, которых ванильный режим командования сейчас не допускает. Нераспределённые — доступные клиенту живые юниты своей команды с разрешённым профилем, не включённые ни в одну сохранённую группу. Автоматический бан исключает hidden/internal, неуправляемые типы и все CoreBlock.unitType; пользователь может переопределить его, но ограничения штатного выбора остаются.
- Размеры задаются в координатах UI. Продольное направление — порядок групп; поперечное — ряды тиров. Направления: вниз, вверх, вправо, влево. Тиры у внутренней стороны располагаются раньше; типы внутри тира возрастают. При недостатке места допускается наложение с приоритетом высокого тира/типа при рисовании и выборе.
- Сторона центра выбирается по расстоянию от середины грани до центра экрана; при равенстве приоритет у боковой грани. Она определяет значок состояния и открываемые настройки. Проекции дополнительно ограничены разрешённой осью: внутренние только вдоль хотбара, внешние только поперёк; сторона на этой оси направлена к центру экрана.
- Три режима продольного распределения: ограниченный (доля 10/11 всех групп), равный адаптивный (доля активных) и пропорциональный (потребность, затем пропорциональное сжатие при нехватке). Пустые группы не занимают место в обычном режиме; в редакторе показаны номинальные направляющие. Поперечный размер выравнивается опционально. Полный алгоритм и исключение двойного резерва описаны ниже.
- Резерв проекции использует подготовленный наибольший разрешённый размер и доступный бюджет, не текущего представителя. Представитель выбирается по состоянию, затем тиру; при равенстве сохраняется прежний. Более высокий приоритет применяется сразу.
- Компрессия: `base + (hitSize - base) * compression`. Вписывание: `min(1, min(доступная ширина, доступная высота) * occupancy / compressed(largest))`. Пользовательский максимум проекции удалён. Ручной largest меняет знаменатель, а не резерв; квадратный минимум внешней области не меняет коэффициент. `resize` применяется **после** вписывания только при рисовании; переполнение не меняет размеры и зоны ввода.
- Сокрытие доступно у края; без проекции остаётся узкая полоса состояния. Наведение анимирует раскрытие отдельной группы. Редактор показывает нормальную геометрию.
- При слишком узкой рамке редактор настроек раскрывается до 480 единиц UI (ограничено окном), не меняя размеров самого HUD. Подпись занимает половину строки, справа находятся переключатели и поля со сбросом. В очень узком окне совмещённое поле переносится ниже переключателя. Его hit-проверка пропускает ввод к четырём граням рамки; переносы текста и прокрутка сохраняют доступность настроек. При фокусе поля удерживается контекст открытого редактора, поскольку DesktopInput временно сбрасывает commandMode.
- Необязательные параметры: выдержка наблюдаемого урона 120 тиков, проверка движения включена. Это интервал индикации, **не** утверждение о максимальной перезарядке ванильного оружия. Порог движения вычисляется по самому медленному управляемому типу; неподвижный приказ движения/патрулирования получает коричневый цвет без значка.
- В настоящем desktop-клиенте 160.7 нет текстуры старого `blockOmegaMechPad`, хотя его константа сохраняется в `Iconc`. При её отсутствии движение обозначается штатной стрелкой `Icon.left`, повёрнутой к стороне центра. Прочие значки берутся по фактическим camelCase-именам `Icon.icons` (проверены генератор и игровой запуск).

## Что подтверждено исходниками

Используются [Mindustry 17012d61 (v160.7)](https://github.com/Anuken/Mindustry/tree/v160.7), [Arc 7445105cd2](https://github.com/Anuken/Arc/tree/7445105cd2).

- `DesktopInput.update()` редактирует массив групп непосредственно; отдельного события нет. Оно же фильтрует выбор по `allowCommand`, валидности и команде. `InputHandler.panCamera` — публичная точка перемещения камеры, desktop-реализация включает panning.
- `TypeIO.writeController/readController` передаёт тип контроллера, цель, позицию, очередь, команду и стойки CommandAI. Это позволяет читать патруль и преследование на клиенте. Обычный AI обновляется только на сервере.
- `TypeIO.writeMounts/readMounts` передаёт флаги стрельбы и точки прицеливания. Оружие обновляется и на клиенте. Наблюдаемый выстрел/непрерывный снаряд надёжнее приказа атаковать; факт попадания по противнику не утверждается.
- `HealthComp.hitTime` — transient, длительность вспышки короткая. Дополнительно сравниваются последовательные значения здоровья/щита. Клиент может пропустить урон между снимками; дистанционное попадание нельзя обещать распознать абсолютно всегда.
- `UnitComp.drownTime` — фактический прогресс утопления. Добыча проверяется через `mining`, строительство через `activelyBuilding`; ремонт по активному лечащему оружию и доступной цели/лучу.
- `UnitType.draw` меняет позицию меха на время рисования, вызывает мировые эффекты, свет, части, способности и виртуальные переопределения. Вызов из HUD небезопасен. Мод рисует подготовленные регионы и читает позы, не вызывая этот метод и не создавая копий игровых юнитов.
- BuildWheel добавляет собственный актор в корень сцены, проверяет `commandMode`, UI-фокус и использует свои обработчики ввода. Control Groups работает дочерним элементом `ui.hudGroup`, не регистрирует глобальных горячих клавиш/перехватчиков и не изменяет обработчики BuildWheel.

## Компоненты и единый поток данных

1. `ModSettings` — проверенные числовые параметры, положение и сохранение в `Core.settings` с собственным префиксом.
2. `UnitProfiles` — один кеш метаданных по ID текущей сессии; настройки по `UnitType.name`. Все зарегистрированные типы остаются в меню. Бан, его исходное значение и largest вычисляются здесь; ванильные значения тиров/типов/цветов заданы таблицей плана. Однократно подготавливаются обрезанные по прозрачности UV иконок, без новых GPU-текстур; неподдерживаемые standalone-регионы сохраняют исходные UV.
3. `GroupModel` — единственный сборщик состава, агрегатов и состояний. Одна запись наблюдений на живого юнита, битовая маска до 11 групп. Общие юниты не классифицируются несколько раз. Переиспользуются списки, счётчики и записи. При выходе из мира ссылки освобождаются.
4. `HudLayout` — чистая геометрия: подготовленные размеры групп/ячеек, направления, адаптация и расположение. Вычисляется при изменении состава, параметров или окна; анимация сокрытия не пересортировывает данные.
5. `GroupsHud` — один рисующий/интерактивный элемент с точечным `hit`, собственным редактором и обычными Arc-контролами настроек. Нет отдельного UI-дерева на каждого юнита. Рисование читает модель; клики повторно проверяют доступность юнитов перед штатным выбором.
6. `UnitProjection` — безопасное рисование выбранных представителей с восстановлением состояния Draw. Неподдерживаемые данные приводят к использованию иконки соответствующего типа, а не вызову чужой отрисовки.
7. `ControlGroupsMod` связывает жизненный цикл клиента, сброс мира и событие урона. На headless UI не создаётся.

Arc не вызывает `act()` у невидимых акторов. Поэтому переключение активности HUD выполняется в `GroupsHud.updateVisibility()`, который родитель проверяет и у скрытого элемента. Там нет обходов юнитов. После повторного открытия следующий `act()` сразу согласовывает данные. Таймеры используют монотонные часы, включая индикацию урона во время скрытия.

## Частоты и стоимость

Частоты сосредоточены в `UpdatePolicy`: составы согласовываются каждые 200 мс, состояния каждые 100 мс реального времени. Пауза не блокирует UI. После открытия, смены мира, правок профилей и переключения нераспределённых согласование немедленное. Изменение чистой геометрии не запускает новый обход юнитов. Когда HUD скрыт, обходов юнитов нет; в строительстве с включённым HUD обновления продолжаются.

Состав: O(числа сохранённых ID + наблюдаемых юнитов), плюс один проход команды только при включённой группе нераспределённых. Динамика: одна классификация на уникального наблюдаемого юнита + агрегация по его членствам. Сортировка типов выполняется только при изменении количества/состава или настроек профиля. Рисование пропорционально отображаемым типам и максимум 11 проекциям, независимо от числа юнитов.

Измерения и игровые ограничения фиксируются отдельно в [VALIDATION.md](VALIDATION.md). Синтетические проверки не заменяют сравнение времени кадра с базовой игрой.

## Распределение геометрии V2

1. Подготавливаются потребности структурных единиц по тирам: иконка, измеренный счётчик, counterGap, промежутки типов/тиров. Иконка `I = S * (B + (H - B) * K) / B` независима от компрессии/вписывания; H ≤ 0 и нечисловые H заменяются B. Заведомо запредельные результаты ограничены 1 000 000 единиц UI для предотвращения переполнения координат. Это не ограничитель ручного resize проекции.
2. Из длины вычитаются кнопка настроек и отступы, получается бюджет A. По метаданным и номинальной доле определяется устойчивый резерв R; внутренний резерв дополнительно ограничен сохранением минимальных кнопок. Для внешних проекций продольный R равен нулю.
3. Единственное вычитание: бюджет структурных единиц `A - ΣR`. Лимит режима относится к полной группе, поэтому структурный лимит равен `cap - R`. При нехватке бюджет распределяется ограниченным пропорциональным алгоритмом, максимум по 11 группам. Если не помещаются даже минимумы, они уменьшаются; при остаточном режиме первым защищается минимум нераспределённых.
4. Полная продольная длина группы — `S + R`. Нераспределённые могут следовать общему режиму, иметь долю 1/11 или получать остаток с защищённым минимумом `min(ввод, длина/3)`. Ввод хранится отдельно от эффективного предела.
5. Внешняя область занимает только поперечное пространство. При квадратном минимуме она увеличивается к центру экрана, вплоть до физических границ окна, без увеличения редактируемой рамки. Вписывание использует исходную область до квадратного расширения. Внутренние проекции используют только R вдоль хотбара; квадратный минимум временно не действует, его предпочтение сохраняется.
6. Подготовленные координаты ячеек сохраняются. Анимация обновляет только показанный прямоугольник и область отслеживания, без измерений шрифта и новых обходов типов/юнитов. Ручной resize применяется в отрисовке последним.

Рамки состояния перекрашивают существующий четырёхпиксельный бордюр Tex.pane, оставляя стандартный чёрный фон. Рамки редактора растут внутрь. Разделитель лежит целиком внутри области проекции. Переключение uiIcon/fullIcon использует физическое разрешение отображения и только существующую более подробную текстуру.

Диагностика opt-in: таймеры операций, счётчики и форматирование работают только при раскрытой «Телеметрии» в видимом редакторе. Монотонные часы рабочих обновлений продолжают работать. Collapser дополнительно ограничивает hit-область видимой частью анимации, поскольку Arc автоматически ограничивает только рисование.
