# Аудит и архитектура Control Groups (Mindustry v160.7)

## Трактовка требований

Исходное задание: [план](../План-набросок%20Хотбара%20юнитов.txt), [правки V2](SPEC_V2.txt), [решения V2](V2_DECISIONS.md). Правила: [AGENTS.md](../AGENTS.md).

- Одно нажатие выбирает группу, тип или представителя проекции. Двойное дополнительно центрирует камеру. Для групп 1–9, 0 используются индексы ванильного массива 0–9.
- Составы только читаются из `InputHandler.controlGroups`. Мод не сохраняет вторую копию групп в настройках, не чистит ванильные ID и не меняет `distinctcontrolgroups`.
- Группа может временно содержать юнита под логикой/игроком. Его состояние показывается, но выбор пропускает юнитов, которых ванильный режим командования сейчас не допускает. Нераспределённые — доступные клиенту живые юниты своей команды с разрешённым профилем, не включённые ни в одну сохранённую группу. Автоматический бан исключает hidden/internal, неуправляемые типы и все CoreBlock.unitType; пользователь может переопределить его, но ограничения штатного выбора остаются.
- Размеры задаются в координатах UI. Продольное направление — порядок групп; поперечное — ряды тиров. Направления: вниз, вверх, вправо, влево. Тиры у внутренней стороны располагаются раньше; типы внутри тира возрастают. При недостатке места допускается наложение с приоритетом высокого тира/типа при рисовании и выборе.
- Сторона центра выбирается по расстоянию от середины грани до центра экрана; при равенстве приоритет у боковой грани. Она определяет значок состояния и открываемые настройки. Проекции дополнительно ограничены разрешённой осью: внутренние только вдоль хотбара, внешние только поперёк; сторона на этой оси направлена к центру экрана.
- Три режима продольного распределения: ограниченный (доля 10/11 всех групп), равный адаптивный (доля активных) и пропорциональный (потребность, затем пропорциональное сжатие при нехватке). Пустые группы не занимают место в обычном режиме; в редакторе показаны номинальные направляющие. Поперечный размер выравнивается опционально. Полный алгоритм и исключение двойного резерва описаны ниже.
- Резерв проекции определяется бюджетом HUD и потребностями структурных единиц, без размеров изображения, occupancy, largest или текущего представителя. Представитель выбирается по состоянию, затем тиру; при равенстве сохраняется прежний. Более высокий приоритет применяется сразу.
- Компрессия: `C(H) = B + (H - B) * K`. Вписывание: `P_i(H) = Z_i * (O / R_i) * C(H) / C(Hmax_i)`; изображение может уменьшаться и увеличиваться. Область Z_i, автоматический Hmax_i и запас R_i принадлежат каждой группе, включая нераспределённых. Переключатель «Общий наибольший юнит» использует одно ручное значение в знаменателях всех групп, сохраняя их собственные области и запасы. Квадратное расширение внешней области может увеличивать её Z_i. `resize` применяется **после** вписывания только при рисовании; переполнение не меняет размеры и зоны ввода. Подробности — ниже.
- Сокрытие доступно у края; без проекции остаётся узкая полоса состояния. Наведение анимирует раскрытие отдельной группы. Редактор показывает нормальную геометрию.
- При слишком узкой рамке редактор настроек раскрывается до 480 единиц UI (ограничено окном), не меняя размеров самого HUD. Подпись занимает половину строки, справа находятся переключатели и поля со сбросом. В очень узком окне совмещённое поле переносится ниже переключателя. Его hit-проверка пропускает ввод к четырём граням рамки; переносы текста и прокрутка сохраняют доступность настроек. При фокусе поля удерживается контекст открытого редактора, поскольку DesktopInput временно сбрасывает commandMode.
- Необязательные параметры: выдержка наблюдаемого урона 120 тиков, проверка движения включена. Это интервал индикации, **не** утверждение о максимальной перезарядке ванильного оружия. Порог движения вычисляется по самому медленному управляемому типу; неподвижный приказ движения/патрулирования получает коричневый цвет без значка.
- В настоящем desktop-клиенте 160.7 нет текстуры старого `blockOmegaMechPad`, хотя его константа сохраняется в `Iconc`. При её отсутствии движение обозначается штатной стрелкой `Icon.left`, повёрнутой к стороне центра. Прочие значки берутся по фактическим camelCase-именам `Icon.icons` (проверены генератор и игровой запуск).

## Что подтверждено исходниками

Используются [Mindustry 17012d61 (v160.7)](https://github.com/Anuken/Mindustry/tree/v160.7), [Arc 7445105cd2](https://github.com/Anuken/Arc/tree/7445105cd2).

- `DesktopInput.update()` редактирует массив групп непосредственно; отдельного события нет. Оно же фильтрует выбор по `allowCommand`, валидности и команде. `InputHandler.panCamera` — публичная точка перемещения камеры, desktop-реализация включает panning.
- `TypeIO.writeController/readController` передаёт тип контроллера, цель, позицию, очередь, команду и стойки CommandAI. Это позволяет читать патруль и преследование на клиенте. Обычный AI обновляется только на сервере.
- `TypeIO.writeMounts/readMounts` передаёт флаги стрельбы и точки прицеливания. Оружие обновляется и на клиенте. Наблюдаемый выстрел/непрерывный снаряд надёжнее приказа атаковать; факт попадания по противнику не утверждается.
- `HealthComp.hitTime` — transient, длительность вспышки короткая. Дополнительно сравниваются последовательные значения здоровья/щита. Клиент может пропустить урон между снимками; дистанционное попадание нельзя обещать распознать абсолютно всегда.
- `UnitComp.drownTime` — фактический прогресс утопления. Добыча проверяется через `mining`, строительство через `activelyBuilding`; ремонт по активному лечащему оружию и доступной цели/лучу.
- `UnitType.draw` меняет позицию меха на время рисования, вызывает мировые эффекты, свет, части, способности и виртуальные переопределения. Вызов из HUD небезопасен. Мод рисует подготовленные регионы и читает позы, не вызывая этот метод и не создавая копий игровых юнитов.
- BuildWheel добавляет собственный актор в корень сцены, проверяет `commandMode`, UI-фокус и использует свои обработчики ввода. Control Groups работает дочерним элементом `ui.hudGroup`, не регистрирует глобальных горячих клавиш/перехватчиков и не изменяет обработчики BuildWheel.

## Компоненты и единый поток данных

1. `ModSettings` — проверенные числовые параметры, положение и сохранение в `Core.settings` с собственным префиксом.
2. `UnitProfiles` — один кеш метаданных по ID текущей сессии; настройки по `UnitType.name`. Все зарегистрированные типы остаются в меню. Бан, его исходное значение и largest вычисляются здесь; ванильные значения тиров/типов/цветов заданы таблицей плана. Однократно подготавливаются обрезанные по прозрачности UV иконок и два радиуса геометрии проекции (обычной/расширенной), без новых GPU-текстур; неподдерживаемые standalone-регионы сохраняют исходные UV. Чистый `ProjectionBounds` вычисляет эти радиусы из поддерживаемых примитивов, не хранит отдельной модели или настроек.
3. `GroupModel` — единственный сборщик состава, агрегатов и состояний. Одна запись наблюдений на живого юнита, битовая маска до 11 групп. Общие юниты не классифицируются несколько раз. Переиспользуются списки, счётчики и записи. При выходе из мира ссылки освобождаются.
4. `HudLayout` — чистая геометрия: подготовленные размеры групп/ячеек, направления, адаптация и расположение. Вычисляется при изменении состава, параметров или окна; анимация сокрытия не пересортировывает данные.
5. `GroupsHud` — один рисующий/интерактивный элемент с точечным `hit`, собственным редактором и обычными Arc-контролами настроек. Нет отдельного UI-дерева на каждого юнита. Рисование читает модель; клики повторно проверяют доступность юнитов перед штатным выбором.
6. `UnitProjection` — безопасное рисование выбранных представителей с восстановлением состояния Draw. Неподдерживаемые данные приводят к использованию иконки соответствующего типа, а не вызову чужой отрисовки.
7. `ControlGroupsMod` связывает жизненный цикл клиента, сброс мира и событие урона. На headless UI не создаётся.

Arc не вызывает `act()` у невидимых акторов. Поэтому переключение активности HUD выполняется в `GroupsHud.updateVisibility()`, который родитель проверяет и у скрытого элемента. Там нет обходов юнитов. После повторного открытия следующий `act()` сразу согласовывает данные. Таймеры используют монотонные часы, включая индикацию урона во время скрытия.

## Частоты и стоимость

Частоты сосредоточены в `UpdatePolicy`: составы согласовываются каждые 200 мс, состояния каждые 100 мс реального времени. Пауза не блокирует UI. После открытия, смены мира, правок профилей и переключения нераспределённых согласование немедленное. Изменение чистой геометрии не запускает новый обход юнитов. Когда HUD скрыт, обходов юнитов нет; в строительстве с включённым HUD обновления продолжаются.

Состав: O(числа сохранённых ID + наблюдаемых юнитов), плюс один проход команды только при включённой группе нераспределённых. Динамика: одна классификация на уникального наблюдаемого юнита + агрегация по его членствам. Сортировка типов выполняется только при изменении количества/состава или настроек профиля. Рисование пропорционально отображаемым типам и максимум 11 проекциям, независимо от числа юнитов.

Измерения и игровые ограничения фиксируются отдельно в [VALIDATION.md](VALIDATION.md). Синтетические проверки не заменяют сравнение времени кадра с базовой игрой.

## Распределение геометрии V2

1. Подготавливаются потребности структурных единиц по тирам: иконка, измеренный счётчик, counterGap, промежутки типов/тиров. Иконка `I = S * (B + (H - B) * K) / B` независима от компрессии/вписывания; H ≤ 0 и нечисловые H заменяются B. Заведомо запредельные результаты ограничены 1 000 000 единиц UI для предотвращения переполнения координат. Это не ограничитель ручного resize проекции.
2. Из длины вычитаются кнопка настроек и отступы, получается бюджет A. Внутренний продольный резерв L начинается с половины номинальной доли активной группы (с учётом меньших лимитов режима и нераспределённых), не более внутренней толщины HUD. Затем он ограничивается доступностью минимальных структурных кнопок и защищённого остаточного минимума. Ни hitSize, ни компрессия, occupancy, ручной Hmax или resize в L не входят. Это разделение геометрического бюджета между изображением и содержимым, а не новый базовый размер изображения.
3. Единственное вычитание: бюджет структурных единиц `A - ΣL`. Лимит режима относится к полной группе, поэтому структурный лимит равен `cap - L`. При нехватке бюджет распределяется ограниченным пропорциональным алгоритмом, максимум по 11 группам. Если не помещаются даже минимумы, они уменьшаются; при остаточном режиме первым защищается минимум нераспределённых.
4. Полная продольная длина группы — `S + L`. Нераспределённые могут следовать общему режиму, иметь долю 1/11 или получать остаток с защищённым минимумом `min(ввод, длина/3)`. Ввод хранится отдельно от эффективного предела. Поперечное пространство внутренней проекции поддерживает квадрат L, если позволяет настроенная толщина; оно не ограничивается одной лишь потребностью структурных ячеек.
5. У внешних проекций L = 0. Поперечная область начинается с меньшего из внутренней длины группы и половины внутренней толщины HUD; структурная часть использует остальную доступную толщину по своей потребности. При квадратном минимуме область увеличивается к центру экрана, вплоть до физических границ окна, без увеличения редактируемой рамки. **Вписывание учитывает окончательное квадратное расширение.** Внутри квадратный минимум временно не действует, его предпочтение сохраняется.
6. После распределения/выравнивания сохраняются полные прямоугольники областей. Из реально доступной части исключаются четырёхпиксельный бордюр панели и разделитель на стороне содержимого, затем один пиксель для растеризации/минимальной толщины линий. Меньшая сторона пригодной области каждой группы — её Z_i. Анимация обновляет только показанный прямоугольник и центр отрисовки; Z_i и коэффициент размера от неё не меняются. Подготовленные координаты ячеек сохраняются, без измерений шрифта и новых обходов типов/юнитов. Ручной resize применяется в отрисовке последним.

## Вписывание по реальной геометрии проекций

P — номинальный размер, соответствующий hitSize, а не обязательно большая сторона текстуры. Рендерер переводит мировые размеры в UI через `P / H`; невалидный H в обоих компонентах заменяется B. Без вписывания сохраняется `P = C(H) * UI-scale`.

После загрузки контента `ProjectionBounds` готовит описанную окружность поддерживаемых спрайтов каждого типа. Учитываются диагонали корпуса/обводки/ячейки, любое вращение оружия и полная отдача, гусеницы, законные позы ног/мехов, двигатели и стандартные RegionPart: крайние перемещения/рост, собственный origin, зеркальность и вложенные якоря. Используется доступный `UnitType.sample` только для определения вида геометрии, без создания или изменения юнитов. Текстурные прямоугольники включают прозрачные поля: оценка консервативная. Физическая граница спрайтов не зависит от hitSize; иконка аварийного fallback, кольцо горения, щит и соединения их линий добавляются при нормализации в HudLayout. Так невалидный hitSize всюду использует текущий B, без закешированной подстановки 8. Ограничения нестандартной анимации перечислены в [STATES_AND_PROJECTIONS.md](STATES_AND_PROJECTIONS.md).

В существующем проходе подготовленных типов вместе с потребностью ячеек для каждой группы собираются её `autoHmax_i = max(H)` и `E_i = max(radius(type) * C(H) / H)`. Повторный обход игровых объектов не нужен. Нераспределённые проходят тот же алгоритм; пересечения сохранённых групп не смешивают их максимумы. При `d = 0,07` (максимальное смещение по каждой оси) запас группы:

`R_i = max(1, 2 * E_i / C(autoHmax_i)) / (1 - 2*d)`.

`F_i = O / R_i`, затем единственная операция размера — `P_i(H) = Z_i * F_i * C(H) / C(effectiveHmax_i)`. Нет ограничения коэффициентом 1 или прежним trackingBase. Ни O, ни геометрический запас не участвуют повторно в резервировании/масштабировании. При выключенном «Общем наибольшем юните» effectiveHmax_i равен автоматическому максимуму группы; при включённом — общему значению из прежнего ручного поля. Автоматическая оценка R_i всегда использует собственный autoHmax_i: ручное значение не может отменить свой эффект через запас. Одинаковый тип теперь может иметь разный размер в разных группах — это требуемое следствие персонального вписывания.

При автоматическом Hmax_i радиус изображения не превосходит `Z_i * O * (1 - 2*d) / 2`; смещение ограничено `d * Z_i`. Вместе это помещается в меньшую сторону области при O ≤ 1, независимо от текущего поворота. После уменьшения геометрии старое плавное смещение сначала ограничивается новым диапазоном. O > 1, общий ручной Hmax и resize намеренно могут нарушать это автоматическое условие, без изменения интерактивной области и без финального зажима изображения.

Один коэффициент размера на группу хранится в double, чтобы отношения экстремальных размеров не переполняли float. Пустые группы/нулевые области и O = 0 дают нулевой адаптированный размер; при K = 0 P одинаковы внутри группы, при K = 1 пропорциональны H. Доля 0–300% принимается редактором и сохраняется без изменения резерва; новый default/сброс — 100%, ранее сохранённые значения сохраняются. Ключи общего ручного максимума и его выбранное значение также сохранены при переименовании настройки. Примитивы с нечисловыми координатами не отправляются в Arc; число сегментов кольца ограничено 256, чтобы экстремальный ручной масштаб не создавал неограниченную работу. Это предел детализации кольца, а не размера изображения.

Рамки состояния перекрашивают существующий четырёхпиксельный бордюр Tex.pane, оставляя стандартный чёрный фон. Рамки редактора растут внутрь. Разделитель лежит целиком внутри области проекции. Переключение uiIcon/fullIcon использует физическое разрешение отображения и только существующую более подробную текстуру.

Диагностика opt-in: таймеры операций, счётчики и форматирование работают только при раскрытой «Телеметрии» в видимом редакторе. Монотонные часы рабочих обновлений продолжают работать. Collapser дополнительно ограничивает hit-область видимой частью анимации, поскольку Arc автоматически ограничивает только рисование.

## Визуал и управление редактором

Панель из восьми иконок находится вне ScrollPane. «Схематика HUD» и «Раскрыть настройки» включены по умолчанию и сохраняются отдельно от параметров геометрии: их setters не увеличивают рабочую revision. Скрытие настроек убирает фон/строки и освобождает их фокус, оставляя панель иконок на прежнем месте. Пустая область пропускает ввод; штатные грани изменения размера и кнопка настроек сохраняются. При скрытом меню телеметрия выключена даже у ранее раскрытого раздела.

Кнопки используют прозрачную рамку с яркостью 0,55/0,75/0,9 и промежутком 4 UI-пикселя, по образцу номерных кнопок BuildWheel. В панели редактора eye/eyeOff нормализованы по ширине list с сохранением пропорций. Исходный зазор внутри двухпиксельной рамки уменьшен с 3 до 2; затем весь набор (изображения, внутренние поля и толщина рамки) масштабируется до стороны кнопки настроек, обычно 44 UI-пикселя. Для панели используются собственные подготовленные TextureRegionDrawable, чтобы глифы действительно масштабировались; округление размеров отдельных картинок отключено, иначе оно нарушало бы равенство ширин. Сброс сохраняет прежний квадрат 40 и рамку; единая строка: начало переключателя/поля, при совмещении переключатель → 5 пикселей → поле → 3 пикселя → сброс. При нехватке ширины поле переносится под переключатель. Вложенность сдвигает целиком строки и их колонки.

У Fonts.getGlyph в v160.7 draw игнорирует переданные width/height и использует натуральные размеры глифа. Поэтому уменьшенная ячейка сама по себе не уменьшает стрелку. Для rightOpen/downOpen используются обычные TextureRegionDrawable поверх тех же регионов, с настоящим половинным размером. Общий слот сохраняет координату текста; отступ вложенного уровня равен фактической ширине уменьшенного downOpen. Заголовки прозрачны, текст желтеет при наведении, открытая стрелка жёлтая. Настройки рисуются поверх схемы, включая всю жёлтую рамку нулевой кнопки.

Tooltip имеют стандартный Styles.black8 без рамки, светло-серый текст и поля по 4 пикселя. Привязка совпадает с UI.addDescTooltip Mindustry, используемым BuildWheel: сверху подсказки находится нижний левый угол элемента, а не позиция мыши. KeepInStage сдвигает подсказку внутрь окна при нехватке места. Ограничение шириной редактора учитывает также поля. Общие стили Mindustry и файлы BuildWheel не изменяются.
