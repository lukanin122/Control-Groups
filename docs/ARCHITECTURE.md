# Аудит и архитектура Control Groups (Mindustry v160.7)

## Трактовка требований

Исходное задание: [план](../План-набросок%20Хотбара%20юнитов.txt). Правила: [AGENTS.md](../AGENTS.md).

- Одно нажатие выбирает группу, тип или представителя проекции. Двойное дополнительно центрирует камеру. Для групп 1–9, 0 используются индексы ванильного массива 0–9.
- Составы только читаются из `InputHandler.controlGroups`. Мод не сохраняет вторую копию групп в настройках, не чистит ванильные ID и не меняет `distinctcontrolgroups`.
- Группа может временно содержать юнита под логикой/игроком. Его состояние показывается, но выбор пропускает юнитов, которых ванильный режим командования сейчас не допускает. Нераспределённые — доступные клиенту живые юниты своей команды с управляемым типом, не включённые ни в одну сохранённую группу.
- Размеры задаются в координатах UI. Продольное направление — порядок групп; поперечное — ряды тиров. Направления: вниз, вверх, вправо, влево. Тиры у внутренней стороны располагаются раньше; типы внутри тира возрастают. При недостатке места допускается наложение с приоритетом высокого тира/типа при рисовании и выборе.
- Сторона центра выбирается по расстоянию от середины грани до центра экрана; при равенстве приоритет у боковой грани. Она определяет выравнивание, сторону проекции, разделителя, значка состояния и открываемых настроек.
- Максимальный размер продольной ячейки резервируется под все 10/11 групп, но пустые группы в обычном режиме не занимают места. Редактор показывает все зарезервированные ячейки. Поперечный размер выравнивается опционально.
- Чтобы переключение представителя не меняло геометрию, зона проекции резервируется по наибольшему подготовленному размеру среди типов **этой группы**. Представитель выбирается по состоянию, затем тиру; при равенстве сохраняется прежний. Более высокий приоритет применяется сразу.
- Компрессия: `base + (hitSize - base) * compression`. Адаптация только уменьшает подготовленный размер, учитывает поперечный/продольный предел и необязательный пользовательский максимум. `resize` применяется **после** адаптации только при рисовании; переполнение не меняет размеры и зоны ввода.
- Сокрытие доступно у края; без проекции остаётся узкая полоса состояния. Наведение анимирует раскрытие отдельной группы. Редактор показывает нормальную геометрию.
- При слишком узкой рамке редактор настроек раскрывается до минимальной читаемой ширины в сторону центра, не меняя размеров самого HUD. Его hit-проверка пропускает ввод к четырём граням рамки; переносы текста и прокрутка сохраняют доступность настроек.
- Необязательные параметры: выдержка наблюдаемого урона 120 тиков, проверка движения включена. Это интервал индикации, **не** утверждение о максимальной перезарядке ванильного оружия. Порог движения вычисляется по самому медленному управляемому типу; неподвижный приказ движения/патрулирования получает коричневый цвет без значка.
- В настоящем desktop-клиенте 160.7 нет текстуры старого `blockOmegaMechPad`, хотя его константа сохраняется в `Iconc`. При её отсутствии движение обозначается штатной стрелкой `Icon.left`, повёрнутой к стороне центра. Прочие значки берутся по фактическим camelCase-именам `Icon.icons` (проверены генератор и игровой запуск).

## Что подтверждено исходниками

Используются [Mindustry 17012d61 (v160.7)](https://github.com/Anuken/Mindustry/tree/v160.7), [Arc 7445105cd2](https://github.com/Anuken/Arc/tree/7445105cd2).

- `DesktopInput.update()` редактирует массив групп непосредственно; отдельного события нет. Оно же фильтрует выбор по `allowCommand`, валидности и команде. `InputHandler.panCamera` — публичная точка перемещения камеры, desktop-реализация включает panning.
- `TypeIO.writeController/readController` передаёт тип контроллера, цель, позицию, очередь, команду и стойки CommandAI. Это позволяет читать патруль и преследование на клиенте. Обычный AI обновляется только на сервере.
- `TypeIO.writeMounts/readMounts` передаёт флаги стрельбы и точки прицеливания. Оружие обновляется и на клиенте. Наблюдаемый выстрел/непрерывный снаряд надёжнее приказа атаковать; факт попадания по противнику не утверждается.
- `HealthComp.hitTime` — transient, длительность вспышки короткая. Дополнительно сравниваются последовательные значения здоровья/щита. Клиент может пропустить урон между снимками; дистанционное попадание нельзя обещать распознать абсолютно всегда.
- `UnitComp.drownTime` — фактический прогресс утопления. Добыча проверяется через `mining`, строительство через `activelyBuilding`; ремонт по активному лечащему оружию и доступной цели/лучу.
- `UnitType.draw` меняет позицию меха на время рисования, вызывает мировые эффекты, свет, части, способности и виртуальные переопределения. Вызов из HUD небезопасен. Мод рисует подготовленные регионы и читает позы, не вызывая этот метод и не создавая копий игровых юнитов.
- BuildWheel добавляет собственный актор в корень сцены, проверяет `commandMode`, UI-фокус и использует свои обработчики ввода. Control Groups работает дочерним элементом `ui.hudGroup`, не регистрирует глобальных горячих клавиш/перехватчиков и не изменяет обработчики BuildWheel.

## Компоненты и единый поток данных

1. `ModSettings` — проверенные числовые параметры, положение и сохранение в `Core.settings` с собственным префиксом.
2. `UnitProfiles` — один кеш метаданных по ID текущей сессии; настройки по `UnitType.name`. Список управляемых типов формируется после загрузки контента; ванильные значения тиров/типов/цветов заданы таблицей плана.
3. `GroupModel` — единственный сборщик состава, агрегатов и состояний. Одна запись наблюдений на живого юнита, битовая маска до 11 групп. Общие юниты не классифицируются несколько раз. Переиспользуются списки, счётчики и записи. При выходе из мира ссылки освобождаются.
4. `HudLayout` — чистая геометрия: подготовленные размеры групп/ячеек, направления, адаптация и расположение. Вычисляется при изменении состава, параметров или окна; анимация сокрытия не пересортировывает данные.
5. `GroupsHud` — один рисующий/интерактивный элемент с точечным `hit`, собственным редактором и обычными Arc-контролами настроек. Нет отдельного UI-дерева на каждого юнита. Рисование читает модель; клики повторно проверяют доступность юнитов перед штатным выбором.
6. `UnitProjection` — безопасное рисование выбранных представителей с восстановлением состояния Draw. Неподдерживаемые данные приводят к использованию иконки соответствующего типа, а не вызову чужой отрисовки.
7. `ControlGroupsMod` связывает жизненный цикл клиента, сброс мира и статистику. На headless UI не создаётся.

Arc не вызывает `act()` у невидимых акторов. Поэтому переключение активности HUD выполняется в `GroupsHud.updateVisibility()`, который родитель проверяет и у скрытого элемента. Там нет обходов юнитов. После повторного открытия следующий `act()` сразу согласовывает данные. Таймеры используют монотонные часы, включая индикацию урона во время скрытия.

## Частоты и стоимость

Частоты сосредоточены в `UpdatePolicy`: составы согласовываются каждые 12 тиков (200 мс), состояния каждые 6 тиков (100 мс). Пауза не блокирует UI: интервалы используют реальное время сцены. После открытия и смены мира согласование немедленное. Когда HUD скрыт/режим командования выключен, обходов юнитов нет; при открытии данные обновляются.

Состав: O(числа сохранённых ID + наблюдаемых юнитов), плюс один проход команды только при включённой группе нераспределённых. Динамика: одна классификация на уникального наблюдаемого юнита + агрегация по его членствам. Сортировка типов выполняется только при изменении количества/состава или настроек профиля. Рисование пропорционально отображаемым типам и максимум 11 проекциям, независимо от числа юнитов.

Измерения и игровые ограничения фиксируются отдельно в [VALIDATION.md](VALIDATION.md). Синтетические проверки не заменяют сравнение времени кадра с базовой игрой.
