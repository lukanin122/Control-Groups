# Решения по заданию версии 2

Требования сохранены без изменений в [SPEC_V2.txt](SPEC_V2.txt). База проверок первой версии — [VALIDATION_V1.md](VALIDATION_V1.md), текущие результаты — [VALIDATION.md](VALIDATION.md).

Порядок реализации: схема настроек и исключение типов → единый расчёт геометрии → рисование и ввод → редактор/профили → регрессии, измерения и настоящий клиент → коммиты и обычный push.

## Единая геометрия

- Продольная ось всегда задаёт порядок групп, поперечная — ряды тиров. Три режима распределения относятся к продольной оси, вне зависимости от ориентации.
- Сначала готовятся потребности структурных единиц. Размеры их иконок/счётчиков не используют компрессию или вписывание проекций. Контрольный размер общий, как в формуле задания; невалидный hitSize заменяется контрольным.
- Области проекций резервируются до распределения содержимого, по устойчивой оценке доступной области и метаданным типов, без зависимости от текущего представителя. Внутренние резервы вычитаются один раз. Лимиты режима относятся к полной продольной длине группы, включая такой резерв.
- Пропорциональный режим при отсутствии переполнения выделяет потребность, а при переполнении распределяет бюджет с минимальными размерами. Остаточная нераспределённая группа сначала защищает свой минимум, затем получает остаток после сохранённых групп. Минимум ограничивается третью общей продольной длины; пользовательское значение в поле не зажимается этим расчётным пределом.
- Внешние проекции расположены только поперёк, внутренние — только вдоль. Квадратный минимум внешней области растёт в сторону центра, не меняет формулу изображения и отключён для внутренних проекций. Если квадрат физически не помещается в окно, область ограничивается окном. Отрицательные размеры не допускаются.
- Ручной наибольший размер меняет знаменатель вписывания, а не резерв. Иначе его изменение увеличивало бы область и отменяло желаемый эффект. Пользовательский resize применяется последним к изображению, без изменения области и ввода.

## Данные, редактор и ввод

- Бан централизован в UnitProfiles, включая автоматические признаки UnitType и все CoreBlock.unitType. Все зарегистрированные типы остаются в меню. Пересчёт метаданных при изменении бана не требует нового игрового обхода; существующее согласование исключает такие типы из всех групп.
- Сокрытие хранится отдельно для командования и строительства. Во время редактирования сохраняется контекст открытого редактора: штатный DesktopInput выключает commandMode при фокусе текстового поля, что не должно закрывать редактор или менять адресуемую настройку сокрытия.
- Выбор из строительства завершает размещение выбранного блока и включает штатный commandMode. Привязки и предпочтение commandmodehold не изменяются: при удерживаемом командовании дальнейшая длительность режима подчиняется штатной клавише. Выбор остаётся сохранённым. Временный глобальный перехват клавиш или имитация постоянно удерживаемой клавиши не вводятся.
- Диагностические таймеры/счётчики и форматирование телеметрии включаются только при открытом разделе в видимом редакторе. Рабочие монотонные часы, согласование и состояния продолжают свою обычную работу.
- Tooltip локальные, светло-серые, с переносом не шире редактора. Исходный вариант без фона переопределён последующим заданием на визуал: теперь используется полупрозрачный Styles.black8 без рамки. Строки сброса используют сохранённые определения значений по умолчанию, включая текущий автоматический размер для ручного наибольшего юнита.
- До первого выбора ручного размера его значение следует актуальным метаданным, даже если другие настройки уже сохранялись. После ввода или включения ручного режима значение фиксируется и сохраняется также при временном отключении этого режима. Сброс использует текущий автоматический размер.
- Для частых проверок бана есть производный boolean-индекс по ID в том же UnitProfiles: это устраняет зависимое чтение Profile на каждом из потенциальных 100 000 членств. Индекс меняется синхронно в save; новых проходов игровых объектов нет. Основные профили и сохранённые значения остаются единственными владельцами настроек.
