# Control Groups

Клиентская Java-модификация Mindustry: хотбар сохранённых групп юнитов в режимах командования и строительства.

- Показывает ванильные группы `Ctrl + 1…9, 0`, количества по типам и приоритетное состояние группы.
- Одиночный ЛКМ выбирает группу, тип или юнита проекции; двойной дополнительно перемещает камеру.
- Редактор позволяет перемещать и растягивать панель, менять направление и настраивать проекции, отступы и скрытие у края.
- Дополнительная группа показывает юнитов своей команды без сохранённой группы.
- Три режима распределения места, отдельное правило нераспределённых, внутренние и внешние области проекций, независимые размеры иконок и счётчиков.
- Тиры, типы, цвета, ручной масштаб и бан сохраняются по именам контента. Все типы доступны в таблице; юниты ядер и технические типы автоматически исключены с возможностью переопределения.
- Редактор разделён на раскрывающиеся разделы, поля имеют сброс. «Сокрытие» независимо сохраняется для командования и строительства. Диагностика включается только при раскрытии телеметрии.
- Английская и русская локализации. Мод не меняет ванильные горячие клавиши и не требует установки на сервер.

## Окружение и сборка

- JDK 17 (проверка: `java -version` и `javac -version`).
- Gradle Wrapper; отдельная установка Gradle не нужна.
- Mindustry **v160.7** и Arc **7445105cd2** — версия Arc взята из исходников Mindustry v160.7.
- Для первой сборки нужен интернет: Wrapper скачивает Gradle, сборка — зависимости из Maven Central и JitPack.

Windows PowerShell:

```powershell
.\gradlew.bat clean build
.\gradlew.bat benchmark
```

Linux/macOS:

```sh
sh ./gradlew clean build
```

Результат: `build/libs/Control-Groups.jar`. Зависимости игры используются только при компиляции и не включаются в JAR. `build` запускает автоматические тесты и проверку содержимого JAR. `benchmark` отдельно измеряет обработку синтетических снимков; результаты не равнозначны времени кадра в игре. Текущая сборка предназначена для настольной Mindustry; Android DEX не создаётся.

## Структура

- [Класс мода](src/main/java/controlgroups/ControlGroupsMod.java) — жизненный цикл клиентского HUD.
- [Метаданные и ресурсы](src/main/resources/) — содержимое, попадающее в корень JAR. Будущие `bundles`, `sprites` и прочие ресурсы размещаются здесь.
- [Конфигурация сборки](build.gradle) и [версии зависимостей](gradle.properties).
- [Правила разработки](AGENTS.md).

Метаданные находятся внутри `src/main/resources`, чтобы Mindustry не загружала рабочую папку репозитория как установленный мод. Для проверки импортируйте собранный JAR через меню модов и перезапустите игру. Не удаляйте папку исходников через меню игры.

Включите режим командования и сохраните группу штатным сочетанием `Ctrl + номер`. Кнопка шестерёнки открывает редактор; значок перемещения можно тянуть, четыре грани рамки изменяют размеры. В редакторе список открывает настройки типов, глаз включает проекцию, стрелка у края включает сокрытие. Поля с недопустимым значением не меняют сохранённую настройку.

HUD по умолчанию виден и при строительстве. Выбор группы/типа/представителя включает командование и отменяет активный предпросмотр размещения, сохраняя очередь строительства. Предпочтение Mindustry «удерживать командование» сохраняет штатное действие: при таком режиме длительность командования зависит от удержания его клавиши. Поля редактора сохраняют фокус даже когда штатный ввод временно выключает командование.

Компиляция не заменяет проверку в игре. Границы точности индикаторов, базовая и расширенная проекции описаны в [STATES_AND_PROJECTIONS.md](docs/STATES_AND_PROJECTIONS.md).

Для автоматического запуска настоящего клиента в невидимом окне есть необязательная задача `smoke`. Каждый запуск использует новый каталог `.gradle/smoke-run/data-*`, создаёт тестовый мир и сохраняет снимки/отчёт в `build/reports/smoke`. Новое окружение также исключает автоматический safe mode после аварийного завершения предыдущего теста. Пользовательские миры и настройки не используются. Нужен локальный настольный дистрибутив игры с `desktop.jar` и доступный OpenGL.

Пример PowerShell (укажите свои абсолютные пути):

```powershell
$env:ORG_GRADLE_PROJECT_mindustryDesktopJar = 'C:/Games/Mindustry/jre/desktop.jar'
$env:ORG_GRADLE_PROJECT_mindustryJava = 'C:/Games/Mindustry/jre/bin/java.exe'
# Необязательно: проверить совместную загрузку с копией BuildWheel.
$env:ORG_GRADLE_PROJECT_buildWheelDirectory = 'C:/Games/Mindustry/saves/mods/BuildWheel'
.\gradlew.bat smoke
```

Для ручного тестирования используйте обычный запуск игры и собранный JAR. Отдельно проверяйте сетевую игру, нестандартные типы/контроллеры и открытие интерфейсов других модов. Совместная загрузка не доказывает отсутствие всех конфликтов.

## Разработка

Для самостоятельных задач создавайте отдельные ветки; `main` изменяется только с разрешения. BuildWheel — независимый связанный проект: его исходники можно читать для анализа совместимости, но нельзя изменять без отдельного задания.

Основные источники API:

- [Mindustry v160.7](https://github.com/Anuken/Mindustry/tree/v160.7)
- [Arc 7445105cd2](https://github.com/Anuken/Arc/tree/7445105cd2)
- [Mindustry API](https://mindustrygame.github.io/docs/index.html)
- [BuildWheel](https://github.com/lukanin122/BuildWheel)

При изменении целевой версии сверяйте `mindustryVersion`, соответствующий `arcVersion` и `minGameVersion` в метаданных. Версия мода задана в `build.gradle` и метаданных; при её изменении обновляйте оба значения.
